# Release Roadmap

**Version:** 0.1 | **Status:** Proposed

## Phase 0 — Foundation

- Project charter and product requirements.
- Validate PNG primary-school curriculum, assessment and reporting requirements.
- Data dictionary and logical database model.
- Architecture and school-isolation decision.
- Security/privacy and offline/sync design.
- MVP acceptance criteria and test plan.
- GitHub backlog and CI foundation.

**Exit:** baseline approved and implementation-ready.

## Release 1 — Core School Administration MVP

- School setup and user/role administration.
- Academic year, periods, grades, classes and subjects.
- Student register and enrolment.
- Class placement and history.
- Daily attendance and summaries.
- Assessment configuration and student results.
- Student report cards.
- Essential school reports, PDF and controlled export.
- Audit, backup/recovery and tested deployment.
- Offline attendance/assessment only if its design and acceptance tests are completed.

**Exit:** all MVP acceptance criteria pass and pilot sign-off is obtained.

## Release 2 — Staff Administration

Potential scope: staff profiles, staff roles, staff attendance, class/subject responsibilities and staff reports. Payroll is not assumed.

## Release 3 — Assets and Resources

Potential scope: equipment register, inventory, furniture, asset allocation, condition and maintenance history.

## Release 4 — Advanced Reporting and School Intelligence

Potential scope: longitudinal academic analysis, attendance trends, cohort comparisons and configurable management dashboards. Any student-level analytics require privacy and fairness review.

## Release 5 — National Interoperability

Potential scope: authorised national data exchange, school identifiers, student transfer package, standard code mappings, versioned APIs and national reporting interfaces. Implement only against confirmed standards, governance and lawful authority.

## Release governance

Each release has its own approved scope, requirements, GitHub milestone, issues, acceptance criteria, test evidence, deployment plan and release report. Later-release work must not delay or expand the MVP without an approved change.
